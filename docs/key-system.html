Key System

Implement access control with key validation.

An opt-in replacement for the stock WindUI key dialog. Everything on the card — layout, thumbnail, header, note, input, footer, status line and every button — is driven from one table.

  • Opt-in only. Passing KeySystem.Layout switches to the modern screen. No Layout, no change: the stock dialog renders exactly as it always has.
  • Reversible. Delete the four-line dispatch at the top of src/components/KeySystem.lua (or just stop passing Layout) and the stock key system is back, untouched. Deleting src/components/KeySystemModern.lua as well leaves no trace.
  • Theme-first. Every colour resolves through ThemeTag, so the card follows the user's active theme. The default accent is the theme's Button key — grey on Dark, not blue. Only Layout.Accent overrides that.
  • Instant open. The card is the first thing mounted, with no intro animation. Layout.Splash adds the optional icon/title intro back in.
  • Nothing is fixed. Thumbnail, header icon, buttons, note, footer and each block's position are all config fields. A block can be nudged with Offset without breaking the flow.
function KeySystem.new(Config, Filename, func, keyValidator)
    if type(Config.KeySystem.Layout) == "table" then
        return require("./KeySystemModern").new(Config, Filename, func, keyValidator)
    end
    -- ... stock path

Quick start#

local WindUI = loadstring(game:HttpGet("..."))()

WindUI:CreateWindow({
    Title = "Premium Tool",
    Author = "you",
    Folder = "PremiumTool",
    Icon = "sparkles",
    KeySystem = {
        Title = "Access Required",
        Note = "Get your key at discord.gg/example - one key per account.",
        KeyValidator = function(key)
            return key == "TEST-KEY"
        end,
        SaveKey = false,
        URL = "https://discord.gg/example",
        Layout = {
            Accent = "Button",
            Radius = 24,
            Padding = 24,
            Gap = 12,
            BodyWidth = 620,
            Header = {
                Kicker = "Secure Access",
                Title = "Access Required",
                Icon = "key",
                Tag = {
                    Title = "v2.5",
                    Color = WindUI:Gradient({
                        ["0"] = { Color = Color3.fromHex("#6B8E23"), Transparency = 0 },
                        ["100"] = { Color = Color3.fromHex("#2F4F4F"), Transparency = 0 },
                    }, { Rotation = 45 }),
                },
            },
            Input = {
                Placeholder = "XXXX-XXXX-XXXX",
                Label = "License key",
                SubmitFill = WindUI:Gradient({
                    ["0"] = { Color = Color3.fromHex("#6B8E23"), Transparency = 0 },
                    ["100"] = { Color = Color3.fromHex("#2F4F4F"), Transparency = 0 },
                }, { Rotation = 45 }),
            },
            Footer = { Align = "Left", Text = "example.com" },
            Status = {
                Success = "Key accepted - loading",
                Duration = 20,
                Errors = {
                    already_used = "This key is already used.",
                    expired = "This key has expired.",
                    revoked = "This key has been revoked.",
                },
            },
            -- Footer defaults to Get Key / Copy key / Exit; passing Buttons
            -- replaces that cluster outright.
            Buttons = {
                {
                    ID = "Copy",
                    Title = "Copy key",
                    Icon = "copy",
                    Slot = "Footer",
                    Style = "Secondary",
                    Action = "CopyKey",
                },
            },
        },
    },
})

Error reasons#

A validator can hand back a reason as the second value and the card maps it to a message. Layout.Status.Errors overrides or extends the built-in set:

KeyValidator = function(key)
    local res = HttpGet("check?key=" .. key)
    if res.ok then return true end
    return false, res.reason    -- "already_used" | "expired" | "revoked" | ...
end

Layout = {
    Status = {
        Errors = {
            already_used = "This key is already used.",
            expired      = "This key has expired.",
            revoked      = "This key has been revoked.",
            banned       = "This key is banned.",
            wrong_account = "This key belongs to a different account.",
            limit        = "Key limit reached, try again later.",
        },
    },
}

Built-in reasons: invalid, already_used, expired, revoked, banned, wrong_account, limit. Any other string returned as the reason is shown as-is.

Splash#

Off by default: the card mounts as the first thing on screen, no intro, no hold. Pass Layout.Splash = true (or a table) when you want the icon-and-title intro — the session icon centred, the window title underneath, then the card.

Layout = {
    Splash = {
        -- all optional; defaults shown
        Show = true,
        Duration = 5,          -- seconds
        Gap = 18,              -- icon-to-title gap
        IconSize = 110,
        TitleSize = 24,
        Breathe = true,        -- slow icon pulse while waiting
        -- Icon = "sparkles",  -- defaults to CreateWindow's Icon
        -- Title = "Ender",   -- defaults to CreateWindow's Title
        -- IconColor = Color3.new(1, 1, 1),
    },
}

Gapnumber18Space between the icon and the title
IconSizenumber110Edge length of the icon
TitleSizenumber24

Titlestringwindow Title
IconColorColor3theme Icon

The splash is a CanvasGroup named Splash; controller.SkipSplash() cuts the wait, and controller.Reveal() does it with the fade. Both are safe to call when the splash is off — Reveal() is what the card fires on mount.

Error animation#

A rejected key shakes the card and flashes a red ring on the input field. Both are independent and both are on by default.

Layout = {
    ErrorAnimation = {
        Shake = true,       -- decaying side-to-side on the whole card
        Flash = true,       -- red ErrorRing on the field
        Amplitude = 10,     -- peak offset in pixels
        Duration = 0.45,    -- seconds
    },
}
FieldTypeDefaultNotes
ShakebooleantrueLayout.Shake = false also disables it
Flashbooleantrue
Amplitudenumber10Peak horizontal offset
Durationnumber0.45Whole animation, ends back at rest

The shake rides the card, not the field: the field lives under a UIListLayout, so parent-level motion is the only offset that does not fight the layout.

Moving elements#

Every block can be nudged without breaking the flow. The nudge is visual only — the block draws shifted, its neighbours keep their slots.

Layout = {
    Header    = { Offset = { 0, -2 } },
    Input     = { Offset = { 0, 14 } },   -- default is { 0, 8 }
    Footer    = { Offset = { 0, 4 } },
    Thumbnail = { Offset = { -8, 0 } },
    Offsets   = {
        Note   = { 0, 6 },
        Status = { 0, -2 },
    },
}

Offset accepts { X, Y } or { X = 0, Y = 6 }. Thumbnail.Offset moves the panel inside the row; Layout.Thumbnail.Position still decides which side it lives on.

Slots

  • Header — right side of the title row, before the close button.
  • Input — inside the key field, right of the clear button.
  • Body — full-width row under the status line.
  • Thumbnail — inside the thumbnail panel, bottom aligned.
  • Footer — footer row.
  • Hidden — never rendered, still reachable through controller.Buttons.

Controller#

local controller = getgenv().WindUIKeySystem -- requires Layout.Debug = true
controller.Submit()               -- run validation with the current text
controller.SetKey("XXXX")         -- set the field's text
controller.SetStatus("error", "Nope")
controller.SetBusy(true)
controller.Shake()
controller.Close()

controller.Buttons.Discord        -- TextButton
controller.Input                  -- TextBox
controller.Frame                  -- CanvasGroup card
controller.Mount                  -- full-screen Frame
